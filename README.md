# مُدارا | ModAra

فروشگاه آنلاین مد و فشن (React + TypeScript + Vite + Tailwind) با تجربهٔ خرید **تک‌صفحه‌ای و داستانی**:
بدون منوی ثابت؛ کشف محصول از طریق اسکرول فصل‌ها انجام می‌شود و همهٔ ابزارها (جستجو، علاقه‌مندی، سبد)
در یک نوار شناور در دسترس‌اند.

## اجرای سریع (بدون هیچ تنظیماتی)

```bash
npm install
npm run dev
```

سپس آدرس نمایش‌داده‌شده در ترمینال را در مرورگر باز کنید (به‌صورت پیش‌فرض `http://localhost:5173`).
سرور روی `0.0.0.0` گوش می‌دهد، بنابراین از طریق آدرس شبکه/پیش‌نمایش هم مستقیماً در کروم قابل باز کردن است.

### حالت دمو (پیش‌فرض)

اگر متغیرهای محیطی Supabase تنظیم نشده باشند، برنامه به‌صورت خودکار از یک بک‌اند محلی داخل مرورگر
استفاده می‌کند (`src/lib/localBackend.ts`) که داده‌های اولیه‌اش از فایل‌های
`supabase/migrations/*.sql` استخراج شده اند (`src/lib/demoSeed.ts`).

در این حالت همه‌ی بخش‌ها کار می‌کنند:

- صفحهٔ اصلی فصل‌محور (آغاز → داستان → دسته‌بندی‌ها → کاتالوگ → خدمات → ژورنال)
- نمایش سریع محصول با گالری، انتخاب سایز/رنگ و بازگشت به همان نقطهٔ اسکرول
- سبد خرید **بدون نیاز به ورود** (مهمان) که با ورود کاربر ادغام می‌شود
- علاقه‌مندی‌ها، جستجوی زنده، کوپن تخفیف (`WELCOME10`) و تسویه‌حساب
- ثبت‌نام / ورود، تاریخچه سفارش‌ها، فاکتور، وبلاگ و پنل ادمین

داده‌ها در `localStorage` نگهداری می‌شوند؛ برای ریست‌کردن، `localStorage` را پاک کنید.

### اتصال به Supabase واقعی

فایل `.env` بسازید (نمونه در `.env.example`):

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=xxxx
```

با وجود این مقادیر، برنامه به‌جای بک‌اند محلی از کلاینت واقعی Supabase استفاده می‌کند. مایگریشن
`supabase/migrations/20260926000000_immersive_commerce.sql` جدول `wishlist` و ستون‌های
`variant`/`discount`/`coupon_code`/`sizes`/`colors` را اضافه می‌کند (idempotent است).

## معماری تجربهٔ کاربری

| مفهوم | پیاده‌سازی |
| --- | --- |
| بدون هدر/منو | `src/components/Header.tsx` فقط لوگو است؛ ناوبری با اسکرول فصل‌ها و `ChapterDots` (نقاط فصل) انجام می‌شود |
| نوار ابزار شناور | `src/components/UtilityBar.tsx` — جستجو، علاقه‌مندی، سبد (بدون منو) |
| نمایش سریع محصول | `src/components/ProductOverlay.tsx` — overlay تمام‌صفحه؛ با `pushState` باز می‌شود تا دکمهٔ Back آن را ببندد و اسکرول صفحه حفظ شود |
| سبد مهمان | `src/lib/guest.ts` + `CartContext` — ذخیره در localStorage و ادغام در حساب هنگام ورود |
| علاقه‌مندی | `WishlistContext` — همان الگوی سبد (localStorage برای مهمان، جدول `wishlist` برای کاربران) |
| واریانت (سایز/رنگ) | `src/lib/variants.ts` — از دسته‌بندی و متن محصول استخراج می‌شود؛ اگر ستون‌های `sizes`/`colors` در DB پر باشند، آن‌ها اولویت دارند |
| کاتالوگ یکپارچه | `src/components/Catalog.tsx` هم به‌عنوان فصل صفحهٔ اصلی و هم به‌عنوان مسیر `#shop` رندر می‌شود |
| ۴۰۴ | مسیر ناشناخته هش به `src/components/NotFound.tsx` می‌رود |

## تصاویر

خط تولید تصاویر با `sharp` اجرا می‌شود و خروجی‌ها کنار عکس اصلی قرار می‌گیرند:

```bash
npm run images   # <name>-640.webp / <name>-1280.webp / <name>-detail.webp
npm run og       # favicon.svg، apple-touch-icon.png و images/og-cover.jpg
```

همهٔ تصاویر سایت از `src/components/ResponsiveImage.tsx` رد می‌شوند (WebP + `srcset` + `loading="lazy"`).
گالری محصول از همان عکس اصلی به‌همراه یک کراپ «جزئیات» ساخته می‌شود.

### تصاویر اختصاصی دسته‌بندی

عکس‌ها بر اساس دستهٔ محصول «آرت‌دایرکشن» مشخص دارند؛ برای هر دسته یک سبک عکاسی و
نسبت تصویر متفاوت (`src/lib/categories.ts`) داریم:

| دسته | آرت‌دایرکشن | نسبت تصویر کارت |
| --- | --- | --- |
| پوشاک | عکس مدل ادیتوریال روی بک‌گراند خاکی/کرم گرم | `4/5` |
| شلوار | مدل استریت‌استایل روی بتن/گچ روشن | `4/5` |
| عینک | پرترهٔ نزدیک زیبایی‌شناختی با گرادیان نرم | `4/5` |
| ساعت | ماکرو مچ روی سنگ، نورپردازی لوکس | مربع |
| کیف | مدل در حال حمل کیف + استیل‌لایف گرم و خنثی | مربع |
| اکسسوری | استیل‌لایف ماکرو مینیمال روی کتان/سنگ | مربع |

عکس‌های شات‌شده (`scripts/image-sources.json` منیفست) در `public/images/<دسته>/` قرار می‌گیرند و
اسکریپت `scripts/build-category-frames.mjs` برای هر منبع سه فریم ادیتوریال می‌سازد:
فریم کامل، کراپ «جزئیات» ۴۶٪ و فریم آینه‌ای. سپس هر محصول را به بهترین فریم داخل
دستهٔ خودش نگاشت می‌کند (نوع کالا +۵، رنگ +۳، مخاطب +۲، توکن اسلاگ +۲) و
`image_url` را در `src/lib/demoSeed.ts` بازنویسی می‌کند؛ دو کارت هیچ‌وقت یک فریم را
تکرار نمی‌کنند و فریم‌های بی‌استفاده خودکار حذف می‌شوند.

```bash
node scripts/build-category-frames.mjs --dry-run   # پیش‌نمایش نگاشت بدون تغییر فایل
node scripts/build-category-frames.mjs             # ساخت فریم‌ها + بازنویسی image_url
npm run images                                     # تولید WebP و حذف خروجی‌های یتیم
```

برای افزودن عکس تازه: فایل jpg را در `public/images/<دسته>/` بگذارید، یک ورودی به
`sources[]` در `scripts/image-sources.json` اضافه کنید و دو دستور بالا را دوباره اجرا کنید.

## سرعت و کارایی

هدف: اولین رنگ‌آمیزی صفحه در کمتر از یک ثانیه روی اتصال متوسط، بدون هیچ درخواست مسدودکننده.

| بهینه‌سازی | جزئیات |
| --- | --- |
| تفکیک مسیرها | `Home` در چانک ورودی می‌ماند و بقیهٔ مسیرها (فروشگاه، وبلاگ، حساب، پنل مدیریت، فاکتور، پرداخت) با `React.lazy` گرفته می‌شوند؛ مسیرهای محتمل بعدی در زمان idle پیش‌گیری می‌شوند |
| SDK تنبل Supabase | `@supabase/supabase-js` (~۱۲۰ کیلوبایت) فقط وقتی اعتبارنامه وجود دارد با `import()` داینامیک بارگذاری می‌شود؛ build دمو هیچ بایتی از SDK را ندارد |
| فونت غیرمسدودکننده | Beiruti با `media="print"` + `onload` بعد از اولین رنگ‌آمیزی بارگذاری می‌شود و متن بلافاصله با فونت سیستم فارسی رندر می‌شود |
| پیش‌بارگذاری LCP | پوستر ویدئوی هیرو با `<link rel="preload" fetchpriority="high">` از قبل گرفته می‌شود |
| ویدئوی موبایل | گوشی‌ها نسخهٔ ۰٫۵ مگابایتی را می‌گیرند، نه master ۲٫۷ مگابایتی |
| چانک‌بندی | React در چانک جدا (کش پایدار بین دیپلوی‌ها)، بقیهٔ وابستگی‌ها در `vendor`، هدف build روی `es2020` |
| سرور توسعه / IDE | `lucide-react` پیش‌باندل می‌شود؛ ورودی ESM آن به‌جای ~۱۵۰۰ فایل آیکون، یک فایل می‌شود |
| تصاویر | WebP + `srcset` + `loading="lazy"` + `decoding="async"` برای همهٔ بیت‌مپ‌ها |
| کاتالوگ تدریجی | ۲۴ کارت اول رندر می‌شوند و بقیه با دکمهٔ «نمایش بیشتر» می‌آیند؛ DOM اولیه حدود ۷۵٪ کم می‌شود |
| وزن‌های فونت | فقط ۵ وزنی که رابط استفاده می‌کند (قبل: ۹ وزن) + پشتیبان فارسی سیستم |

اندازهٔ بارگذاری اولیهٔ build دمو (gzip، بدون کوکی کش):

```
entry + react + vendor + css   ~96 کیلوبایت   (قبل: ~122 کیلوبایت)
```

## انتشار

ورک‌فلوی `.github/workflows/deploy.yml` با هر پوش روی `main` پروژه را build و منتشر می‌کند.
چون Pages این ریپو را زیر مسیر `/Modara/` سرو می‌کند، `vite.config.ts` هنگام build مقدار
`base` را روی `/Modara/` می‌گذارد و همهٔ تصاویر با تابع `asset()` (در `src/lib/format.ts`)
نسبت به همان مسیر ساخته می‌شوند. برای انتشار روی دامنهٔ اختصاصی یا ریشهٔ سایت:

```bash
BASE_PATH=/ npm run build
```

فایل `netlify.toml` نیز در ریشهٔ پروژه تنظیمات build و redirectهای SPA برای Netlify را دارد.
